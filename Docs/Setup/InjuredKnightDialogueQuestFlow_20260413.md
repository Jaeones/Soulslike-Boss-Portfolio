# InjuredKnight 대화 / 퀘스트 수락 흐름 정의 (2026-04-13)

## 문서 목적
- `InjuredKnight`와의 상호작용을 통해 다이얼로그를 열고, 플레이어가 퀘스트를 수락/거절할 수 있는 최소 구조를 정의한다.
- 이 문서는 인벤토리/다이얼로그 구현 스레드와 퀘스트 시스템 구현 스레드가 공통으로 참조하는 계약 문서다.
- 실제 UI 구현, 실제 텍스트 연출, 세부 데이터 에셋 포맷은 이 문서의 직접 범위가 아니다.

## 상호작용 시스템 정의
- 대상 시스템:
  - NPC 상호작용
  - 다이얼로그 진행
  - 선택지 분기
  - 퀘스트 수락/거절 상태 반영
- 사용 씬:
  - `developScenes.unity` 또는 InjuredKnight가 배치되는 진행 씬
- 플레이어 행동:
  - NPC 근처 진입
  - 상호작용 입력
  - 대사 넘기기
  - 수락/거절 선택
- 관련 UI:
  - 상호작용 프롬프트
  - 대화창
  - 선택지 UI
- 저장 상태 영향:
  - InjuredKnight 관련 대화 단계
  - 퀘스트 제안 여부
  - 퀘스트 수락/거절 여부
- 기준 문서:
  - `Docs/Rules/InventoryDialogueInteractionThreadRules.md`
  - `Docs/Rules/QuestStoryThreadRules.md`
  - `Docs/Setup/QuestSystemFlowContract_20260325.md`

## 구조 요약
- 데이터 구조:
  - `InjuredKnightQuestState`
  - `DialogueSequence`
  - `DialogueChoice`
- 입력 흐름:
  - `E` 상호작용 -> 대화 시작 -> 대사 진행 -> 선택지 표시 -> 결과 반영
- 상호작용 시작 조건:
  - 플레이어가 `InjuredKnight` 상호작용 범위 안에 있음
  - 다른 전투/상호작용 잠금 상태가 아님
- 종료 조건:
  - 일반 대사 종료
  - 수락 또는 거절 선택 완료
  - 강제 종료 입력 또는 거리 이탈 시 취소 가능 여부는 구현 스레드에서 결정
- 상태 반영:
  - 수락 시 퀘스트 관련 상태 상승
  - 거절 시 거절 상태 저장
  - 재상호작용 시 현재 상태에 따라 다른 대사 분기

## 권장 상태 정의
### `InjuredKnightQuestState`
- `None`
  - 아직 만난 적 없음
- `Offered`
  - 첫 제안을 들은 상태
- `Accepted`
  - 퀘스트를 수락한 상태
- `Declined`
  - 퀘스트를 거절한 상태
- `Completed`
  - 퀘스트 완료 상태
- `Failed`
  - 필요 시만 사용. 현재는 선택 사항

## 기본 상호작용 흐름
### 1. 첫 조우
- 플레이어가 `InjuredKnight`에 상호작용한다.
- 상호작용 라벨:
  - `대화하기`
- 다이얼로그 시작:
  - InjuredKnight가 자신의 상황과 요청을 짧게 설명한다.
- 종료 방식:
  - 마지막에 선택지 2개 표시
    - `도와주겠다`
    - `지금은 어렵다`

### 2. 수락
- 선택:
  - `도와주겠다`
- 상태 변화:
  - `InjuredKnightQuestState = Accepted`
- 권장 부가 처리:
  - 퀘스트 목표 표시 또는 로그
  - 후속 진행 오브젝트/NPC 활성화
- 이후 재상호작용:
  - 진행 중 대사 출력
  - 동일 제안 반복 금지

### 3. 거절
- 선택:
  - `지금은 어렵다`
- 상태 변화:
  - `InjuredKnightQuestState = Declined`
- 권장 부가 처리:
  - 퀘스트를 완전히 닫지 않음
  - 추후 재상호작용 시 다시 제안 가능
- 이후 재상호작용:
  - 짧은 재제안 대사 출력
  - 다시 수락/거절 선택 가능

### 4. 완료 후
- 상태:
  - `Completed`
- 재상호작용:
  - 완료 후 고정 대사
  - 수락/거절 선택지 제거

## 구현 단위 표
| 단위 | 역할 | 입력 | 출력 | 저장 영향 | 관련 스레드 |
|---|---|---|---|---|---|
| `InjuredKnightInteractable` | NPC 상호작용 진입점 | 플레이어 상호작용 | 대화 시작 요청 | 없음 또는 상태 조회 | 인벤토리/다이얼로그 |
| `DialogueManager` | 대화 진행 제어 | 시퀀스 데이터, 선택 입력 | 다음 대사, 선택지 | 없음 | 인벤토리/다이얼로그 |
| `DialogueSequence` | 대사 데이터 | 상태 기반 참조 | 대사 노드 | 없음 | 인벤토리/다이얼로그 |
| `DialogueChoice` | 수락/거절 선택 | 플레이어 선택 | 선택 결과 이벤트 | 상태 변경 트리거 | 인벤토리/다이얼로그 |
| `InjuredKnightQuestState` | NPC 퀘스트 단계 저장 | 선택 결과, 완료 이벤트 | 분기 기준 | 저장 필요 | 저장/퀘스트 |
| `QuestStateResolver` | 대사 결과를 퀘스트 상태에 반영 | 수락/거절 결과 | 상태 갱신 | 저장 필요 | 퀘스트 |

## 대화 규칙
- 첫 대화는 길게 설명하지 않는다.
- 플레이어가 `왜 요청을 받는지`, `무엇을 결정해야 하는지`만 명확하면 된다.
- 수락/거절은 반드시 마지막 선택지에서 처리한다.
- 대사창이 상태를 직접 저장하지 말고, 결과 이벤트를 통해 퀘스트 상태 쪽으로 전달한다.

## 퀘스트 반영 규칙
- 수락:
  - 퀘스트 단계 또는 별도 NPC 퀘스트 상태가 상승해야 한다.
- 거절:
  - 거절 상태는 저장하되, 영구 차단으로 만들지 않는다.
- 재수락:
  - `Declined` 상태에서 재대화 시 다시 `Accepted`로 전환 가능하게 한다.
- 완료:
  - 완료 후에는 선택지 루프를 종료한다.

## HUD / 전투 충돌 처리
- 대화 중에는 플레이어 일반 입력을 잠그는 것이 권장된다.
- 락온, 공격, 회복 등 전투 입력은 대화 중 비활성화하는 편이 안전하다.
- 대화 UI는 보스 HP UI, 일반 상호작용 프롬프트와 충돌하지 않게 별도 우선순위를 가져야 한다.

## 저장 반영 최소안
- 최소 저장 필드:
  - `injuredKnightQuestState`
- 선택 저장 필드:
  - `injuredKnightDialogueSeen`
  - `injuredKnightQuestAcceptedAtLeastOnce`
- 최소 원칙:
  - 수락/거절 이후 재대화 분기만 안정적으로 복구되면 된다.

## 권장 구현 순서
1. `InjuredKnightInteractable` 추가
2. 대화 시작/종료가 가능한 `DialogueManager` 최소 버전 연결
3. 수락/거절 선택지 2개 구현
4. `InjuredKnightQuestState` 저장/복구 연결
5. 상태별 재대화 분기 추가

## 검증 포인트
- `E - 대화하기`가 정상적으로 표시되는가
- 첫 대화 종료 시 선택지가 뜨는가
- 수락 시 `Accepted`가 저장되는가
- 거절 시 `Declined`가 저장되는가
- 다시 대화하면 상태에 맞는 다른 대사가 나오는가
- `Continue` 후에도 수락/거절 분기가 유지되는가

## 후속 전달 메모
- 퀘스트/스토리 스레드에 필요한 정의:
  - InjuredKnight가 왜 이 퀘스트를 제안하는지
  - 수락 시 플레이어 목표가 무엇인지
- 저장 스레드에 필요한 반영:
  - `injuredKnightQuestState` 저장/복구
- 게임 루프/UI 스레드에 필요한 연결:
  - 대화 중 입력 잠금
  - 선택지 UI 표출
