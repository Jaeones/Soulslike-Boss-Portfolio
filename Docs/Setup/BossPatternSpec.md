# 보스 패턴 명세 초안

## 문서 분류
- 문서 유형: 세팅/콘텐츠 스펙 문서
- 역할: 보스의 페이즈별 패턴 의도, 역할, 구현 연결점을 정리한 문서다.

## 문서 목적
이 문서는 보스 패턴을
기획 명세,
현재 코드 구현,
앞으로의 보강 포인트
세 축으로 같이 보기 위해 만든 초안이다.

현재 프로젝트는 보스 FSM과 전투 뼈대는 갖춰져 있지만,
패턴 기획값이 위키 기준 문서로 정리되어 있지는 않다.
이 문서는 그 공백을 메우기 위한 첫 기준안이다.

## 우선 참조 문서
1. `Docs/Reports/ProgressReport.md`
2. `Docs/Setup/CombatDamagePipelineGuide.md`
3. `Docs/Setup/GameLoopExperienceGuide.md`

## 원본 참고 메모
이 문서는 기존 Notion `팀 프로젝트`의 아래 문서를 재해석해 정리한 초안이다.

- `보스 패턴`
- `콘텐츠 개발`

주의:
- `보스 패턴`은 초기 기획 아카이브 문서다.
- `콘텐츠 개발`은 보스 FSM/패턴 작업 로그 성격이 강하다.
- 따라서 이 문서는 "현재 코드와 연결 가능한 패턴 명세"로 재정리한다.

## 패턴 설계 목표
- 1페이즈는 플레이어가 거리와 타이밍을 읽게 만든다.
- 2페이즈는 압박과 범위를 키워 전투 리듬을 바꾼다.
- 각 패턴은 역할이 겹치지 않게 구성한다.
  - 근거리 압박
  - 광역 견제
  - 회피 유도
  - 돌진/거리 압축
  - 큰 후딜을 가진 리스크/리턴 패턴

## 페이즈 구조
### 1페이즈 의도
- 학습 중심
- 플레이어가 보스의 기본 리듬을 읽게 한다.
- 과도한 속도보다 "무게감"과 "읽히는 텔레그래프"가 중요하다.

### 2페이즈 의도
- 압박 강화
- 기존 회피 습관을 일부 흔든다.
- 속도, 범위, 추격성 또는 광역기를 추가해 전투 긴장을 높인다.

## 1페이즈 패턴 초안
| 패턴명 | 유형 | 설명 | 기획 메모 |
|---|---|---|---|
| 횡베기 | 광역 근접 | 전방 넓은 부채꼴 범위를 베는 기본 광역기 | 옆회피보다 거리 조절 판단 요구 |
| 내려찍기 | 근거리 강공격 | 큰 선딜 후 강한 일격 | 후딜이 커서 딜 타임 제공 |
| 당겨오기 | 제어/CC | 플레이어를 끌어와 후속 압박으로 이어지는 패턴 | 단독 데미지보다 흐름용 |
| 자루 치기 | 근접 견제 | 너무 붙은 플레이어를 밀어내는 빠른 패턴 | 거리 재설정용 |
| 회전 베기 | 360도 견제 | 뒤잡기나 근접 압박에 대한 주변 공격 | 보스 주변 장악용 |

## 2페이즈 패턴 초안
| 패턴명 | 유형 | 설명 | 기획 메모 |
|---|---|---|---|
| 블러드 웨이브 | 원거리 | 파동/검기 형태의 중거리 견제 | 회피 방향 학습 유도 |
| 죽음의 춤 | 연속 난무 | 전진하며 여러 번 베는 압박 패턴 | 스태미나 관리 압박 |
| 단두대 | 필살기/점프 | 넓은 범위에 큰 피해를 주는 고위험 패턴 | 명확한 회피 타이밍 필요 |
| 영혼 수확 | 돌진/잡기 | 빠르게 거리 압축 후 큰 피해 또는 후속타 | 공간 장악용 |

## 현재 코드와의 연결 해석
### 현재 구현에서 확인되는 축
- `BossController`
- `EnemyBase`
- 보스 FSM:
  - `Idle`
  - `Move`
  - `Action`
  - `Groggy`
  - `Dead`
- 현재 `ProgressReport.md` 기준 구현 패턴:
  - `Slam`
  - `Stomp`
  - `Dash`

### 해석
- 현재 구현된 `Slam`은 `내려찍기` 계열로 볼 수 있다.
- `Stomp`는 광역/근거리 견제 패턴 축으로 볼 수 있다.
- `Dash`는 거리 압축 또는 2페이즈 확장 패턴의 기반 축으로 볼 수 있다.
- 즉 현재 코드는 "기획 패턴 전체 구현"보다는,
  1페이즈 핵심 패턴 축을 먼저 시스템화한 상태로 해석하는 편이 맞다.

## 패턴 명세를 위키에 넣을 때 중요한 규칙
### 기획 이름과 코드 이름을 분리해서 기록한다
- 위키에는 `기획 패턴명`과 `현재 코드 구현명`을 함께 적는 편이 좋다.
- 이유:
  - 팀원마다 보는 기준이 다르기 때문이다.
  - 기획자는 "횡베기"로 기억하고, 구현자는 `Slam`이나 `Dash`로 볼 수 있다.

### 패턴 역할을 먼저 본다
- 실제 이름보다 중요한 건 역할이다.
- 예:
  - 거리 압축용
  - 광역 견제용
  - 후딜 제공용
  - 플레이어 근접 견제용

### 현재 구현 여부를 분리한다
- `기획 초안`
- `현재 구현`
- `미구현`
세 상태를 구분해서 기록해야 혼동이 줄어든다.

## 현재 기준 패턴 연결표 초안
| 기획 역할 | 기획 패턴 후보 | 현재 코드 대응 | 상태 |
|---|---|---|---|
| 강한 단발 근접기 | 내려찍기 | `Slam` | 부분 반영 |
| 근거리 광역 견제 | 회전 베기 / 발구르기 계열 | `Stomp` | 부분 반영 |
| 거리 압축 | 영혼 수확 / 돌진 계열 | `Dash` | 부분 반영 |
| 끌어오기 / 제어 | 당겨오기 | 없음 | 미구현 후보 |
| 원거리 견제 | 블러드 웨이브 | 없음 | 미구현 후보 |
| 연속 난무 | 죽음의 춤 | 없음 | 미구현 후보 |
| 2페이즈 필살기 | 단두대 | 없음 | 미구현 후보 |

## 판정/연출 주의사항
- 대형 무기 패턴은 룸 크기와 충돌해서 같이 봐야 한다.
- 공격 판정은 한 덩어리 박스 콜라이더로 시작하더라도,
  이후 무기 날/자루 차등 판정으로 확장 가능성을 열어둔다.
- 2페이즈 패턴은 단순 데미지 상승보다
  리듬 변화와 플레이어 대응 변화가 느껴지는 쪽이 중요하다.

## 플레이 테스트 체크포인트
1. 각 패턴의 선딜이 읽히는지
2. 회피 성공 후 반격 타이밍이 존재하는지
3. 락온 상태에서도 패턴 실루엣을 읽을 수 있는지
4. 벽/기둥 때문에 패턴이 부자연스럽게 보이지 않는지
5. 2페이즈가 단순 수치 상승이 아니라 체감 변화로 느껴지는지

## `Slam / Stomp / Dash` 역할 검증 기록
이 섹션은 ``Slam / Stomp / Dash` 역할 체감과 미구현 패턴 후보 분리 검증` 인계 항목의 종료 지점을 고정하기 위한 기록 섹션이다.
실제 검증이 끝나면 아래 형식으로 결과를 남긴다.

```md
### YYYY-MM-DD 패턴 역할 검증
- 검증 상태:
- 확인한 패턴:
- 역할 분리 체감:
- 회피/반격 체감:
- 미구현 후보 분리 결과:
- 후속 전달 대상:
- 메모:
```

현재 상태:
- `2026-03-19` 임시검증 기록 반영 완료
- 현재는 활성 검증 문서가 아니라 보관 기준 문서로 본다.
- 패턴 수치나 연출 변경이 생기면 새 검증 항목으로 다시 연다.

### 2026-03-19 패턴 역할 검증
- 검증 상태:
  - Closed
- 확인한 패턴:
  - `Slam`
