# 핵심 게임 루프 / 경험 가이드

## 문서 분류
- 문서 유형: 세팅/경험 스펙 문서
- 역할: 팀 프로젝트의 원래 기획 의도와 현재 구현 구조를 연결해서, 플레이어가 어떤 흐름을 경험해야 하는지 기준을 정리한 문서다.

## 문서 목적
이 문서는 현재 프로젝트의 시스템 구현이
어떤 플레이 경험을 만들기 위한 것인지 빠르게 이해할 수 있도록 만든다.

특히 아래 항목을 같은 문서에서 보게 하는 것이 목적이다.
- 기획상 의도한 핵심 게임 루프
- 현재 코드 기준으로 실제 대응되는 시스템
- 아직 연출/콘텐츠로 메워야 하는 빈 구간

운영 규칙은 `Docs/Rules/ThreadOperationRules.md`,
현재 구현 상태는 `Docs/Reports/ProgressReport.md`를 기준으로 본다.

## 원본 참고 메모
이 문서는 기존 Notion `팀 프로젝트`의 아래 문서를 재해석해 정리한 초안이다.

주의:

- 따라서 이 문서에서는 현재 코드 구조와 충돌하지 않는 범위만 공식 기준 후보로 추린다.

## 목표 경험 한 줄 요약
- 플레이어는 짧은 진입 구간에서 긴장을 예열한 뒤, 보스 조우 연출을 거쳐 1:1 결투에 들어가고, 보스 처치 또는 플레이어 사망을 기준으로 명확한 결말 피드백을 받는다.

## 목표 게임 루프
### 1. 진입
- 음산한 복도 또는 보스룸 진입 직전 구간에서 긴장감을 만든다.
- 전투 전에 시선 유도, 공간 인지, 조우 준비를 끝내게 한다.

현재 구현 대응:
- 기준 씬: `Assets/00Game/00Scenes/developScenes.unity`
- 공간/트리거 기준 프리팹:
  - `Assets/00Game/02Prefabs/BossZone/BossZoneTrigger_Entrance.prefab`
  - `Assets/00Game/02Prefabs/BossZone/FogWall_Entrance.prefab`
  - `Assets/00Game/02Prefabs/CheckPoint/Checkpoint_Start.prefab`

### 2. 조우
- 보스 등장 연출이나 시선 집중 구간으로 "이제 본 전투가 시작된다"는 감각을 준다.
- 보스전 시작 시 일반 탐색 상태와 다른 카메라/음향/UI 상태 전환이 필요하다.

현재 구현 대응:
- `BossZoneTrigger`
- `BossFightFlowCoordinator`
- `FogWallController`
- `UIBossHealthBar`
- 보스전 BGM 재생 흐름

### 3. 결투
- 1페이즈에서는 거리 읽기, 회피, 딜 타이밍 학습이 중심이다.
- 2페이즈에서는 속도/범위/압박이 커지며 전투 리듬이 바뀌어야 한다.
- 플레이어는 락온, 회피, 가드, 에스투스를 모두 사용하게 된다.

현재 구현 대응:
- 플레이어:
  - `PlayerController`
  - 상태 머신(`Idle / Move / Roll / Attack / Guard / UseItem`)
  - `LockOnSystem`
  - `PlayerEstusFlask`
- 보스:
  - `BossController`
  - `EnemyBase`
- 전투 판정:
  - `WeaponHitBox`
  - `BossHitbox`
  - `ShockwaveHitbox`

### 4. 결말
- 보스 처치 또는 플레이어 사망 시 플레이 흐름이 분명하게 닫혀야 한다.
- 플레이어 사망 시 `YOU DIED`, 리스폰, 체크포인트 복귀가 자연스럽게 이어져야 한다.
- 보스 처치 시 보스전 종료와 공간 해제가 명확해야 한다.

현재 구현 대응:
- `GameLoopManager`
- `PlayerRespawnFlow`
- `CheckpointManager`
- `CheckpointRegistry`
- `UIYouDied`
- 보스전 종료 이벤트 및 안개벽 해제 흐름

## 현재 프로젝트 기준 경험 포인트
### 플레이어가 반드시 체감해야 하는 것
- 락온 시 카메라가 전투 모드로 바뀐다는 점
- 구르기와 가드의 차이를 실제 공격 대응에서 체감할 수 있다는 점
- 보스존 진입 시 공간이 닫히고 전투가 시작된다는 점
- 사망 후 체크포인트로 돌아가 재도전 루프가 자연스럽다는 점

### 아직 더 보강되어야 하는 것
- 조우 컷신/보스 등장 연출의 명확한 구분
- 보스 2페이즈 전환 연출과 판정 기준
- 보스 처치 후 결말 UI 또는 연출 기준
- 진입로 구간과 보스룸의 역할 차이를 더 강하게 느끼게 하는 환경 연출

## 현재 구현을 이 기준으로 해석할 때의 핵심
### 이미 갖춰진 축
- 1:1 보스전 루프의 시스템 뼈대
- 체크포인트 기반 재도전 구조
- 락온/카메라 전환 구조
- 플레이어 전투 입력과 상태 전이 구조
- 보스전 UI/안개벽/BGM 시작-종료 흐름

### 위키에서 더 명확히 해야 하는 축
- "왜 이 시스템이 필요한가"에 대한 경험 목표 설명
- 보스 1페이즈/2페이즈를 어떤 감정 곡선으로 볼 것인지
- 플레이 테스트 시 무엇을 "성공"으로 볼지에 대한 기준

## 플레이 테스트 기준 해석
이 문서를 기준으로 플레이 테스트를 할 때는
버그만 보는 것이 아니라 아래 경험 흐름이 성립하는지 같이 본다.

1. 보스존 진입 전 준비 구간이 있는가
2. 보스존 진입 시 전투 시작 체감이 분명한가
3. 락온/회피/가드/에스투스를 모두 써야 할 이유가 있는가
4. 사망 후 재도전 루프가 끊기지 않는가
5. 보스전 종료 시 시작 전 상태와 다른 명확한 결말이 있는가

## 진입 -> 조우 -> 결투 -> 결말 루프 검증 기록
이 섹션은 `보스전 기본 루프 재검증` 인계 항목의 종료 지점을 고정하기 위한 기록 섹션이다.
실제 검증이 끝나면 아래 형식으로 결과를 남긴다.

```md
### YYYY-MM-DD 루프 검증
- 검증 상태:
- 확인한 구간:
- 성공 기준 충족 여부:
- 이슈 요약:
- 후속 전달 대상:
- 관련 리포트:
- 메모:
```

현재 상태:
- `2026-03-19` 임시검증 기록 반영 완료
- 현재는 활성 작업 문서가 아니라 보관 기준 문서로 본다.
- 루프 회귀가 생기면 새 검증 항목으로 다시 연다.

### 2026-03-19 루프 검증
- 검증 상태:
  - Closed
- 확인한 구간:
  - `진입 -> 조우 -> 결투 -> 결말`
  - 플레이어 사망 루프
  - 보스 처치 루프
- 성공 기준 충족 여부:
  - 임시검증 기준 충족
- 이슈 요약:
  - 없음
- 후속 전달 대상:
  - 없음
- 관련 리포트:
  - `Docs/Reports/ThreadHandoffInbox.md`
- 메모:
  - 이번 결과는 임시검증 기준이며, 장시간 회귀 검증은 필요 시 별도 항목으로 다시 연다.

## 현재 읽을 때의 기준
- 루프 상태만 확인할 때는 위 `2026-03-19 루프 검증`만 보면 된다.
- 세부 경험 설명은 아래 본문을 참고하고, 활성 이슈 여부는 `ThreadHandoffInbox.md`를 먼저 본다.

## 현재 기준으로 위키에 연결하면 좋은 위치
- `00. 시작하기`
  - 프로젝트 핵심 경험 요약
