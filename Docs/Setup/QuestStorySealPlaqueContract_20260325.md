# SealPlaque 계약서 (2026-03-25)

## 목적
- `SealPlaque`의 서사 의미와 구현 규칙을 고정한다.
- 이 문서는 `SealPlaque`를 단순 인터랙션 오브젝트가 아니라 `문턱 수락 장치`로 해석하게 만드는 기준이다.
- 대상 범위는 시작 구간 이후, 메인 보스 진입 직전이다.

## 핵심 의미
- `SealPlaque`는 길을 여는 열쇠가 아니다.
- `SealPlaque`는 플레이어가 `이 결투를 피하지 않고 받아들이겠다`고 선언하는 장치다.
- 앞선 시체와 시작 구간 위협이 `경고`였다면, `SealPlaque`는 그 경고를 읽은 뒤 내리는 `선택`이다.

## 플레이어 경험 목표
- 플레이어는 `SealPlaque`를 보고 이것이 장식물이 아니라 문턱 장치라고 이해한다.
- 플레이어는 상호작용 전후에 `이제 뒤로 물러서지 않고 안으로 들어간다`는 감각을 받아야 한다.
- 보스 진입은 우발적 충돌이 아니라, `SealPlaque` 이후 감수한 결투처럼 읽혀야 한다.

## 상태 계약
### 입력 상태
- 권장 입력 상태:
  - `goalKnown == true`
- 허용 입력 상태:
  - `goalKnown == false`

### 출력 상태
- 기본 출력:
  - `sealAccepted = true`
- 권장 보정:
  - `goalKnown == false` 상태에서 상호작용한 경우 아래 동시 세팅 허용
  - `goalKnown = true`
  - `sealAccepted = true`

### 상태 의미
- `goalKnown`
  - 문턱이 있다는 사실과 안으로 가야 할 이유를 이해한 상태
- `sealAccepted`
  - 그 문턱을 통과하겠다고 스스로 받아들인 상태

## 상호작용 규칙
### 상호작용 전
- `SealPlaque`는 시각적으로 주변과 분리되어 보여야 한다.
- 플레이어는 이것이 `조사할 가치가 있는 장치`라고 느껴야 한다.
- 중간보스를 넘은 뒤 자연스럽게 시선이 닿는 위치에 있어야 한다.

### 상호작용 시
- 플레이어 입력 1회로 처리한다.
- 즉시 `sealAccepted`가 세팅된다.
- 텍스트, 소리, 문양 점등, 주변 공기감 변화 중 최소 1개 이상 피드백을 준다.

### 상호작용 후
- 플레이어는 보스 진입 방향으로 자연스럽게 이동해야 한다.
- `SealPlaque`는 같은 의미를 반복 설명하지 않는다.
- 이후 플레이어 경험은 `선택 후 전진`으로 읽혀야 한다.

## 권장 문구 방향
### 문구 원칙
- 길게 설명하지 않는다.
- 세계관 고유명사를 남발하지 않는다.
- `문턱`, `대가`, `수락`, `전진` 중 한 축만 남긴다.

### 권장 톤
- 짧고 단호하다.
- 해설이 아니라 선언에 가깝다.
- 플레이어를 겁주기보다 선택을 요구한다.

### 예시 문구 방향
- `이 너머의 길은 대가 없이 열리지 않는다.`
- `지나가려면 받아들여라.`
- `문턱은 도망치는 자를 통과시키지 않는다.`

### 비권장 방향
- 긴 설정 설명
- 보스 정체를 직접 해설하는 문장
- 아이템 열쇠처럼 읽히는 문장

## 연출 계약
### 최소 연출
- 아래 중 최소 1개는 반드시 있어야 한다.
- 석판 문양 점등
- 짧은 저음 효과음
- 안개 농도 변화
- 주변 조명 또는 바람 변화

### 연출 의도
- `무언가가 열렸다`보다 `무언가를 받아들였다`가 더 강하게 읽혀야 한다.
- 물리적 개방보다 심리적 전환이 먼저다.

### 비권장 연출
- 과도하게 거대한 이벤트
- 장시간 컷신
- 보스 등장 전체를 대신하는 연출

## 씬 배치 기준
- 중간보스 뒤에 둔다.
- 플레이어가 전투 직후 바로 볼 수 있는 위치가 좋다.
- `BossZoneTrigger_Entrance`와 너무 멀면 안 된다.
- 시작 지점에서 강하게 보이면 안 된다.
- `SealPlaque` 단독으로 모든 의미를 설명하려 해서는 안 된다.

## 트리거 계약
### 필수 결과
- `sealAccepted = true`

### 선택적 보정
- `goalKnown == false`라면 `goalKnown = true` 동시 세팅 허용

### 후속 연결
- `BossZoneTrigger_Entrance`는 `sealAccepted` 이후 더 자연스러운 진입 조건으로 읽혀야 한다.
- 사망 후 복귀해도 `sealAccepted`는 유지된다.

## 실패/복귀 규칙
### `SealPlaque` 상호작용 전 사망
- 복귀 시:
  - `sealAccepted == false`
- 감각:
  - 아직 문턱을 받아들이지 않았다.

### `SealPlaque` 상호작용 후 사망
- 복귀 시:
  - `sealAccepted == true`
- 감각:
  - 선언은 끝났다. 다시 넘으면 된다.

### `Continue` 시
- 복구 시:
  - `sealAccepted` 유지
  - `bossFightStarted`는 `false`로 정규화
- 감각:
  - 전투 한복판이 아니라 문턱 직후 재도전 상태로 돌아온다.

## 구현 체크리스트
- `SealPlaque`가 장식물이 아니라 상호작용 대상으로 읽히는가
- 상호작용 후 `sealAccepted`가 확실히 세팅되는가
- 사망 후에도 `sealAccepted`가 유지되는가
- `Continue` 후에도 `sealAccepted`가 유지되는가
- `SealPlaque` 상호작용 전후 체감 차이가 있는가
- `SealPlaque`가 열쇠 오브젝트가 아니라 선언 장치로 읽히는가
